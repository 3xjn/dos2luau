# Compiler scope

The compiler accepts COM and DOS MZ executables, a narrow 32-bit i386 COFF object subset, and a narrow 32-bit LE subset. MZ headers are removed from `image` and DOS relocations are retained for the loader. Recognized LZEXE 0.90 and 0.91 stubs are unpacked offline before discovery; malformed or unrecognized LZ-marked stubs fail with an error. The implementation follows the public-domain UNLZEXE utility distributed with LZEXE 0.91e by Fabrice Bellard; attribution and links are in `src/lzexe.ts`. COFF links local section symbols with DIR32/REL32 relocations; other relocation types and unresolved externals are rejected. LE supports fixed 32-bit objects with raw pages and no imports or fixups. LX, PE, NE, compressed LE pages, and LE fixups are rejected. The 32-bit decoder discovers a conservative subset and directly lifts selected register, arithmetic, absolute memory and branch instructions; other discovered instructions use the interpreter. It discovers 16-bit control flow conservatively and emits budget-aware functions for discovered entry points and combines up to 16 adjacent direct instructions. MOV immediate and register-to-register, accumulator and register arithmetic, conditional branches, near jumps, absolute DS memory loads/stores, selected x87 loads, stores, register arithmetic, trigonometry and constants, NOP and INC/DEC are lifted directly; other known instruction boundaries call the runtime interpreter. Discovery stops at unknown or truncated encodings, records a warning in metadata and CLI output, and allows the dispatcher to interpret those addresses. Instructions containing MZ relocation words always use the interpreter. Indirect targets can be added using `--trace-log` lines containing hexadecimal `CS:IP` keys, relative to the image load segment. A guarded fast path omits overwritten flags across a sequence of register ADD, SUB, INC, DEC, and CMP operations ending in CMP only when the instruction budget guarantees the entire sequence executes. Adjacent CMP/Jcc instructions share a block with a budget checkpoint and materialized flags. JSON trace input accepts numeric packed keys or {version:1,blocks:[{relCS,ip}]}. Trace input is a discovery hint, not a proof of coverage. 16-bit operand/address-size overrides are decoded conservatively and run through the interpreter. General x87 native lifting and general flag liveness optimization are not implemented. Every architectural flag is retained for observable instruction boundaries.

Usage: `bun compiler/src/cli.ts program.exe --out runtime/Out [--assets directory] [--trace-log trace.txt]`. The asset packer recursively writes raw bytes under relative DOS-style paths. Blocks are emitted in files of at most 1500 functions; the generated Blocks.luau merges the chunks. The reported direct/fallback counts describe discovered instruction blocks, not execution frequency.
